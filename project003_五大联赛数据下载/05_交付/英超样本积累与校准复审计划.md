## 3. daily-pipeline 持续采集操作

每日在体彩开售后、开球前运行（同日开球一组）：

```powershell
python C:\Users\Administrator\.codex\skills\football-quant-fusion-suite\skills\football-quant-fusion\scripts\fusion_cli.py daily-pipeline --kickoff-date YYYY-MM-DD
```

- 采集→预测→登记→赔率移动全自动，英超/西甲/意甲/德甲/法甲及韩职、北欧、巴甲等竞彩在售赛事都会入样本；
- 快照默认 T-7h（`--snapshot` 可换 closing 等）；
- 次日 `settle` 步骤自动回填赛果，样本计入"已结算"；
- 先 `--dry-run` 预检再实跑；跑完用进度跟踪脚本确认入账。

### 自动化

**已注册 Windows 计划任务 `Codex-FusionDailyPipeline`（2026-08-02，已实测运行成功）**：

- 触发器：每天 10:00；命令：`run_daily_pipeline.ps1`（默认采集当天开球场次）；
- 日志：`04_素材/daily_pipeline_logs/YYYY-MM-DD.log`；
- 管理：
  - `schtasks /run /tn Codex-FusionDailyPipeline`（手动触发）
  - `schtasks /delete /tn Codex-FusionDailyPipeline /f`（停用）
  - 如需采集"明天"的场次，手动运行 `run_daily_pipeline.ps1 -KickoffDate <日期>` 即可。
- 注意：10:00 运行的时刻若当日部分比赛已开球，已开球场次会被 record 正确拒绝
  （"kickoff already passed"），未开球场次正常登记——这属于预期保护，不是故障。

## 4. 英超 200+ 后的校准复审流程

当 `track_epl_sample_progress.py` 显示英超 ≥200 时，按以下顺序执行：

1. **时间序列切分**：按 kickoff 排序，前 60% 训练 / 20% 验证 / 20% 测试（或扩展窗口），
   只使用已结算 closing 样本；
2. **拟合**：在训练段重拟合 1X2 校准层（draw multiplier + temperature，复用核心引擎
   的拟合路径，不另造平行校准器）；
3. **对比**：测试段上比较「当前 BIG5 参数 vs 重拟合参数」的 Brier / Log Loss / ECE /
   argmax 命中（用 `backtest_big5_fusion.py` 的评估口径）；
4. **决策**：仅当测试段指标改善且样本支持时才更新 `config`/`version_manifest`，
   否则维持现状并在复盘记录；
5. 同步更新 `05_交付/样本进度.json` 与复盘。
