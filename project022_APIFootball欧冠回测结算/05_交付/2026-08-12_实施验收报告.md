# APIFootball 欧冠回测结算实施验收报告

## 验收结论

已完成 APIFootball 欧冠赛果 fallback 的实现与只读验收。默认结算路径仍仅调用体彩官方结果；只有显式传入 `--apifootball-fallback` 时才调用 APIFootball。普通完赛、唯一身份匹配且 90 分钟比分可验证的记录才允许结算；加时、点球、身份歧义和来源冲突均不会自动写入正式回测结果。

本次没有执行真实写库结算，真实数据验收使用 `--dry-run`，所以汇总中的 `settled=0` 是预期结果，不代表功能未工作。

## 数据与安全边界

- APIFootball 只补赛果，不替代赛前体彩赔率基线，也不直接制造独立 edge。
- 仅 `score_90_status=verified` 可进入正式结算。
- 检测到加时或点球字段、但无法确定 90 分钟比分时，状态为 `needs_review`。
- 已有结果与供应商比分不一致时，状态为 `source_conflict`，不会静默覆盖。
- 模糊名称不自动匹配；只有带证据的别名可以进入配置。
- API key 只从用户级环境变量 `APIFOOTBALL_COM_KEY` 读取，不写入参数归档、候选数据、报告或错误信息。
- `--date` 同时约束 API 请求和登记库扫描；验收中已从错误的全库 460 条扫描修正为目标日 5 条。
