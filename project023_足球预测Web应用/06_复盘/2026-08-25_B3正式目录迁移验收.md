本次真实启动还暴露并修复了两个单元测试未覆盖的 Windows/运行态缺陷：

1. Task 4 提交的四个 `.bat` 在工作区是 bare LF。Windows cmd 真实复现为 `'ocal' is not recognized`、`'d' is not recognized`、`The system cannot find the file .bat.`。先增加失败回归测试，再用仅作用于四个入口的 `.gitattributes` 固定 CRLF；修复提交 `343cd430`。
2. 首次正式服务在 8767/PID 23952 启动后，全量测试中的 launcher 用例调用 fake uvicorn，却把真实 `workbench.json` 覆盖后删除。随后 fail-closed 启动无法复用无 state 的 8767，因而在 8768/PID 26180 建立额外正式实例。根因是 `write_runtime_state(path=RUNTIME_STATE)` 在函数定义时绑定真实路径，monkeypatch 无效。改为调用时解析 `RUNTIME_STATE`，并让测试显式使用 `tmp_path`、断言真实 state 字节不变；修复提交 `63e75d8a`。

纠偏清理没有按端口或进程名强杀：8767/PID 23952 通过本任务持有的原启动 PTY 会话关闭；8768/PID 26180 同时核验 live contract PID、listener owner、正式 cwd、命令行和本任务创建来源后，按精确 PID 清理。测试写入的无效正式 state 指向不存在的 PID 25144/8767，在确认 PID 与 endpoint 均不存在后删除；随后从正式入口重新启动，得到当前可信 8767/PID 21780。该例外裁决不适用于未知来源的 worktree PID 24296。

`02_脚本/stop.bat` 只调用身份校验后的 `launch.py --stop`。停止前必须同时满足 state identity、state PID、实时 contract build identity 与 process ID；否则 fail closed。本次没有为了测试停止最终正式服务，也没有绕过停止器去处理旧 worktree 服务。
