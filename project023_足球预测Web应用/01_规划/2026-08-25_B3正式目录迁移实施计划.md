# B3 工作台正式目录迁移实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已经验收的 B3 工作台完整提升到正式 `project023_足球预测Web应用`，让启动、停止、测试和维护不再依赖 `.worktrees/b3-web-workbench`。

**Architecture:** 以当前 B3 工作树作为 Web 代码候选源，以正式主工作区 `project018` 作为量化引擎与共享事实库的唯一来源。迁移采用“先建立正式目录失败测试，再分层提升后端与前端，最后备份并切换 SQLite、启动器和运行进程”的顺序；工作树保留为只读回滚源，不删除。

**Tech Stack:** Python 3、FastAPI、Uvicorn、SQLite、原生 JavaScript ES modules、Node.js test runner、Windows Batch、PowerShell、pytest。

**Spec:** `project023_足球预测Web应用/01_规划/2026-08-25_B3正式目录迁移设计.md`

## Global Constraints

- 正式量化脚本固定读取 `F:/HM足球比赛预测/project018_技能工作区整合/02_脚本/skill/football-quant-fusion/scripts`。
- 正式共享事实库固定读取 `F:/HM足球比赛预测/project018_技能工作区整合/04_素材/shared-data/football-quant-fusion`。
- 正式启动、停止和运行路径不得包含 `.worktrees`。
- 迁移不修改模型参数、校准参数、推荐门禁、策略金额、版本清单、发布锁、预测登记、赛果或策略快照。
- 不合并不同 `model_version + probability_signature` 的样本。
- SQLite 仅保存 Web 后台任务状态；迁移前必须分别备份正式目录和 B3 工作树的 `app.db`，迁移后采用 B3 数据库。
- 不提交数据库备份、PID、日志、缓存、临时截图或 `data/runtime/workbench.json`。
- 不删除 B3 Git 工作树，不使用 `git reset --hard`、`git checkout --` 或递归删除。
- 启动器优先使用 8766；端口被占用时只复用身份完全匹配的 B3，否则选择受控空闲端口。
