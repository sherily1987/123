# project023 足球预测 Web 应用 — 方案设计

日期：2026-08-15
目标：把现有散装 CLI 流水线（体彩采集 / LLM 证据轨 / 量化轨 / 回测 / 报告）包装成**本地 Web 应用**，浏览器访问 localhost，一键完成"采集→预测→下注建议→回测"。

## 1. 现状盘点（可复用资产）

| 模块 | 位置 | 形态 | 复用方式 |
|---|---|---|---|
| 体彩采集 | project015/02_脚本/fetch_sporttery_full.py | CLI | subprocess 调用 |
| LLM 预测（3 模型投票+EV） | C:\Users\Administrator\football-llm-predictor\predict.py | CLI | subprocess 调用 |
| 回测 | 同上 backtest.py | CLI | subprocess 调用 |
| 量化无赔率预测 | project021/02_脚本/predict_no_odds.py | CLI | subprocess 调用 |
| 量化联赛档位 | project021/05_交付/full_backtest.json + league_tiers() | 数据+函数 | 读 JSON |
| 证据文件 | C:\...\data\evidence_YYYY-MM-DD\*.md | 文件 | 读取 |
| PPT/报告生成 | build_ppt_*.js / parse_predictions.py | 脚本 | subprocess 调用 |

## 2. 架构

```
浏览器（02_脚本/static/index.html，原生 HTML+JS，无构建）
   │ fetch JSON
FastAPI（02_脚本/app.py，uvicorn，端口 8765）
   ├─ 采集路由：/api/collect → subprocess fetch_sporttery_full.py → 存 SQLite
   ├─ 预测路由：/api/predict → 轻量证据生成 → subprocess predict.py → 解析 → 存 SQLite
   ├─ 量化路由：/api/quant → 读 full_backtest 档位 + 可选 predict_no_odds 单场
   ├─ 回测路由：/api/backtest → 采赛果(sectionsNo999) → subprocess backtest.py
   ├─ 导出路由：/api/export → 报告 md + PPT
   └─ 存储：SQLite（02_脚本/data/app.db）— 场次表 / 预测表 / 回测表
```

## 3. 关键设计决策

1. **subprocess 复用现有 CLI**：predict.py / backtest.py 等保持单一事实源，不做代码复制（用户规则：合并一个版本，不分裂）。本应用只做调度与界面。
2. **轻量证据自动生成**（`light_evidence.py`）：一键预测时自动生成合规六类证据 md——体彩赔率异动（官方接口✅）、联赛/球队身份+近况（维基赛季页 curl✅）、天气（open-meteo✅）、主客场地（维基✅）；伤停/首发类自动标注缺口（与 08-15 手工采集的降级口径一致，门禁 `evidence_gap=true` 但 `ok=true` 可通过）。深度证据（伤停新闻等）留手动补充入口：页面可上传证据文件覆盖。
3. **LLM 轨依赖环境变量**：DEEPSEEK_API_KEY / 智谱 / ARK（已持久化本机）。无 key 时预测按钮报错并提示。
4. **单机单用户**：无登录、无鉴权；只绑定 127.0.0.1。
5. **历史数据**：SQLite 存采集/预测/回测记录；每销售日一个快照，页面可按日期浏览。

## 4. MVP 范围（v1）

- 首页：一键"采集当前在售场次"→ 列表展示（编号/联赛/对阵/开球/赔率/量化档位标注）
- 预测：一键"跑 48 场预测"（轻量证据自动生成 + 3 模型 + EV 下注建议），进度条轮询
- 结果页：预测总表（方向/强度/下注建议/比分/EV）+ 正 EV Top 推荐
- 回测：一键"采赛果+回测"（方向命中/官方赔率对比/比分命中）
- 导出：报告 md + PPT
- 不做（v2+）：用户账号、多设备、深度证据自动搜索、定时任务

## 5. 分期

- v1（本轮）：核心链路端到端（采集→预测→展示→回测→导出）
- v2：量化单场预测接入页面、历史回测聚合指标、证据增强入口
- v3：打包（pyinstaller 后加启动脚本）、配置界面（API key/模型池）

## 6. 风险

- subprocess 调 predict.py 单场 3 模型约 40-70 秒，48 场约 30-40 分钟——页面必须做后台任务+轮询，不能阻塞请求。
- 体彩接口偶发 567/超时——采集重试 2 次。
- 轻量证据的伤停类全是缺口 → predict.py 的 EV 风控会偏向"不下注"——这是诚实行为，界面要解释清楚（轻量证据=降级口径，深度证据可手动补充后重跑）。
