# project023 足球预测工作台

本地网页，对着融合库看板。量化登记走正式 `market_only`，回测只手动点，没有定时任务。

## 启动 / 关闭（只手动，不自动）

- 推荐入口：双击 `启动B3工作台.bat`。
- `启动工作台.bat` 只为旧快捷方式保留，会转交到 `启动B3工作台.bat`。
- 直接运行 `02_脚本/app.py` 也只会转交 `launch.py`，不会另起固定 8765 的无身份服务。
- 以启动窗口实际显示的动态 URL 为准，不要把 8765、8766 或其他端口写死。启动器优先尝试 8766；若该端口属于其他构建，会在受控范围内选择下一个空闲端口。
- 多个启动入口同时运行时会经过 Windows 跨进程启动锁；第二个入口等待同一 `starting` owner 就绪后复用，超时则安全退出，不另选端口覆盖 state。
- 关闭原启动窗口可以停止由该窗口启动的服务；也可以双击 `02_脚本/stop.bat`。停止器会同时核对 runtime state 与实时 `/api/ui-contract` 的构建身份和 PID，不匹配时会拒绝终止进程。

没有计划任务，也不自动启动。

## 页面做什么

- **刷新看板**：拉体彩已开售场次，对照 `backtest/registry.jsonl` 正式登记
- **采集销售日**：`fusion_cli collect --sales-day YYYY-MM-DD`，写入 fusion `forward/`
- **补登记未预测**：只对「有 HAD、未开球、还没登记」的场次跑 `fusion_cli record`，`mode=market_only`
- **每日100元购买策略**：随看板刷新，按所选日期显示胜平负、进球数、半全场、比分单关及 2串1/3串1；已开球自动排除
- **手动结算**：`fusion_cli settle`，读 `results/`
- LLM 列只显示工单里的证据方向，**不当概率，不和量化合成**
- 底部研究库：赛前动态伤停 / 首发采集计数，不进 1X2；首发采用开球前 24 小时起的动态窗口轮询，不依赖单一 T-75 时刻。

唯一模型与数据事实源仍是 `project018_技能工作区整合/`：量化脚本来自其正式 skill 目录，共享预测、赛果和策略快照来自 `04_素材/shared-data/football-quant-fusion/`。`project023` 的 SQLite 只记录 Web 后台任务状态，不是预测库。

`.worktrees/b3-web-workbench` 只保留为只读回滚参考，不是正式运行依赖，也不应作为日常启动目录。正式运行、维护和测试均从当前 `project023_足球预测Web应用` 进行。

每日策略属于用户授权的固定娱乐预算模式，未验证正EV，也不是已发布的生产胆项或凯利仓位；候选不足时保留余额，不用缺失数据强行凑满。
前端生成策略时会把刚读取的权威销售日作为 `expected_sales_day` 交给服务端；服务端在同一跨进程锁内再次核对、生成、提交前复核，并以临时文件加原子替换保存。销售日中途变化会返回 HTTP 409，前端不缓存该响应。

## 本地运行数据

`02_脚本/data/app.db` 是历史遗留的已跟踪活动库，本轮不删除或替换；它只保存 Web 后台任务，不是模型事实库。迁移/修复前备份必须使用 SQLite backup API，不能在服务写入时复制数据库文件。`data/runtime/`、`data/migration-backup/`、SQLite WAL/SHM/journal、`app.local.db` 和本地备份后缀已由项目级 `.gitignore` 隔离。未来若要把活动库完全移出 Git，应另开迁移任务并保留可恢复备份与历史核对，不能在日常修复中直接 untrack 或删除。
