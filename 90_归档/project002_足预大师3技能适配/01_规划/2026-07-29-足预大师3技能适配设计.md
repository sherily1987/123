# 足预大师 3 技能适配设计

## 目标

将已安装在 `C:\Users\Administrator\.codex\skills\zu-yu-dashi-3` 的技能适配到当前 Windows + Codex 环境，同时保留微信接收目录中的原始文件不变。

## 修改范围

1. 修复 `SKILL.md`、`references/*.md` 与 `scripts/predict.py` 中已经损坏的中文文本。
2. 将 `/var/minis/skills/zu-yu-dashi-3/scripts/predict.py` 改为基于技能目录定位脚本的 Windows 可执行方式。
3. 将 `/var/minis/workspace/zu-yu-3/...` 改为当前项目文件夹内的归档规则。
4. 保持预测算法、字段名、JSON 输入输出结构和模型权重不变。
5. 不修改 `zu-yu-dashi-2`、`ucl-predictor` 或微信接收目录中的原始技能。

## 路径设计

- 技能根目录：`C:\Users\Administrator\.codex\skills\zu-yu-dashi-3`
- 预测脚本：技能根目录下的 `scripts\predict.py`
- 项目产物：当前项目的 `projectXXX_项目名称` 文件夹
- 单场预测建议归档：`05_交付\足球预测\{date}_{safe_slug}\`
- 中间文件：`raw_sources.json`、`model_input.json`、`model_output.json`、`report.md`

技能说明不得依赖固定用户名或固定盘符。调用脚本时，Codex应先解析当前技能目录，再向 Python 传入输入 JSON 的绝对路径。

## 编码设计

- 所有文本文件统一保存为 UTF-8。
- JSON 读写显式使用 UTF-8。
- Windows 终端输出由脚本保持 Unicode JSON；必要时设置 Python UTF-8 模式。
- 修复乱码只恢复语义，不改变预测逻辑。

## 验证方案

1. 技能结构与 YAML frontmatter 校验。
2. Python AST 语法校验。
3. 最小输入：仅赔率，验证 `market_only`。
4. 完整输入：赔率 + Elo + 显式 xG，验证 `model_first` 或 `hybrid`。
5. 批量输入：验证 `{ "matches": [...] }`。
6. 失败输入：缺少 Tier-0、字段不成对、非法赔率。
7. 检查输出 JSON 可解析、概率基本守恒、免责声明中文正常。
8. 搜索残留的 `/var/minis` 和典型乱码字符。

## 验收标准

- Codex 能在 Windows 上按技能说明定位并运行 `predict.py`。
- 技能文件无 `/var/minis` 硬编码。
- 中文内容可正常阅读。
- 原始预测算法和结构未被改动。
- 所有代表性测试通过。
- 微信原始文件保持不变。

## 风险与回退

- 乱码文本无法逐字还原时，依据技能结构、字段名和预测代码恢复等价中文语义。
- 修改前记录已安装副本的文件哈希；若验证失败，可从微信原始目录重新复制恢复。
- 当前 Workspace 不是 Git 仓库，无法提交设计文档或用 Git 回退，因此以原始微信目录作为只读备份。
