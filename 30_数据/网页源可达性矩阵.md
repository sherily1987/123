# 网页源可达性矩阵（LLM 证据轨）

> 实测日期 2026-08-16。方法：同一 URL 跑两条路径对照——普通桌面 UA 的纯 HTTP
> （httpx / curl），与无头 Chromium 真浏览器渲染（Playwright 1.62，`playwright_fetch.py`）。
> 未使用任何指纹伪装、验证码求解或反检测补丁。

## 头号结论：多数「未取到」不是被反爬挡住的

`data/evidence_2026-08-15/` 里 56 处伤停缺口、7 处外盘缺口，长期被当成封锁问题。
实测**不是**：Transfermarkt 伤停表、OddsPortal 1X2、jleague 赛程的正文都在服务端
HTML 里，纯 HTTP 就能拿到。历史上的失败是**抽取/截断问题**——这些页面 HTML 体量为
128KB～764KB，`web_extract` 或朴素读取容易只取到导航骨架就返回。

所以处理顺序是：**先纯 HTTP 并确认关键字段真的在正文里 → 拿不到再上浏览器 → 遇人机
验证记缺口**。`playwright_fetch.py` 默认就按这个顺序走（`--browser-only` 可跳过第一步）。

## 封锁项：不绕过

fbref / forebet / whoscored 返回 Cloudflare 人机验证页，besoccer 直接 406。
真浏览器同样过不去——它们拦的不是渲染能力。**这四个按缺口记录，不做绕过**，
依据 `CRAWL4AI_EVIDENCE.md` 第 5 条（验证码/登录/付费墙不得绕过）。

~~后果：fbref 是 xG 与韩职的唯一来源~~ **两项都已找到替代（2026-08-16）**：xG 走
understat（限五大联赛），韩职走 transfermarkt `RSK1` + kleague.com 官方 + portal
公开接口。**fbref 本身仍然封着且不绕过**——账号有会员的话，人工登录导出是合规路径。
详见 [[30_数据/APIfootball数据契约]]「韩职可用源」「xG 来源」两节。

仍无替代的：五大联赛以外的 xG（韩职/日职/沙职），forebet 的模型概率交叉。

## 403 的处理（sofascore）

sofascore 对纯 HTTP 返回 403，真浏览器正常 200，且没有验证码环节。
`fetch_http_first` **不会**自动把 403 升级到浏览器重试——换个客户端硬闯明确的服务端
拒绝，是绕过的开端。需要时由人显式加 `--browser-only`，并对该源的使用方式负责。

## 用法

```bash
cd "/f/HM足球比赛预测/project018_技能工作区整合/02_脚本/llm/football-llm-predictor"
.venv/Scripts/python.exe playwright_fetch.py \
  --url "https://www.transfermarkt.com/laliga/verletztespieler/wettbewerb/ES1" \
  --url "https://www.fotmob.com/leagues/47/overview/premier-league" \
  --out-dir data/crawl_snapshots/manual
```

输出每源一份可审计快照（URL、final_url、状态、判定、正文哈希、正文；不含 cookie 或
凭据），并打印缺口清单。**快照不是主证据**——写入 `evidence_NNN_*.md` 仍须走
`crawl_evidence.py` 的来源清单 + 关键词验证 + 跨域门槛。
