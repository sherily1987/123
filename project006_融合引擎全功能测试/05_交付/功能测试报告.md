## 三、本次发现并修复的问题

1. **settle 的 Windows 临时路径 bug**：`settle_from_sporttery.py` 硬编码 POSIX `/tmp/_settle_results.json`，Windows 下解析为 `\tmp\...` 导致 FileNotFoundError。已改为 `tempfile.gettempdir()`。
2. **wechat-images 缺依赖**：soccer-lottery 桥接脚本需要 `bs4`，已安装到内置 Python 3.12（beautifulsoup4 4.15.0）。
3. **market-ablation 提示文案错误**：fusion_cli 对 market-ablation 也提示"football-data-enrich 可先用…"，已改为按子命令输出正确文案。
4. **上一轮遗留修复确认**：`market_freshness_meta` NameError 注入、`recommendation_policy.py` 补位到 `__pycache__`，本次全链路复测均正常。
5. **Python 3.14 兼容（本轮）**：新增 `scripts/runtime.py`（`resolve_python()` 解析内置 3.12）；`fusion_predict.py` 在非 3.12 下自动 subprocess 重执行（Windows 下 execv 对含空格路径引号不可靠，改用 subprocess），`fusion_cli.py` / `fusion_daily_pipeline.py` 的子进程解释器统一为 `PY`。T7/T30 复测通过，record 在 3.14 下成功登记。

## 四、运行环境约束（重要）

- **Python 3.12 兼容层**：融合核心依赖 `cpython-312.pyc`；系统 Python 3.14 现在也能跑 predict/record/collect——`runtime.py` 会自动把子进程切到内置 3.12。仍建议默认直接用内置 Python 3.12。
- **FUSION_CORE_DIR**：用户级环境变量已设置，但新开 shell 不保证继承；运行时如报核心引擎找不到，先显式设置：
  `$env:FUSION_CORE_DIR='C:\Users\Administrator\.codex\skills\football-quant-fusion-suite\skills\zu-yu-dashi-3\scripts'`
- **盘口新鲜度语义**：`observed_at` 按"相对开球时间"判定（FRESH<6h/AGING<12h/STALE<24h/OUTDATED≥24h），并非"相对当前时间"；远离开球日采集的官方盘口会被判过期并阻断，属设计门控。
- **无市场锚预测**：体彩未开售时用 Elo/λ 走 model_first，输出 `UNFITTED_NO_VALUE`，不得声称 edge。
- **双存储提示**：`fusion_cli odds-add` 写入核心 store（`zu-yu-dashi-3/odds/movement.jsonl`），`daily-pipeline` 写入融合 store（`football-quant-fusion/odds/production_movement.jsonl`），后续建议统一。
