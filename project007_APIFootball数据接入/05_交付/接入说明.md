# API-Football v3 接入说明

## 1. 认证与额度

- Base URL：`https://v3.football.api-sports.io`
- 认证：请求头 `x-apisports-key: <key>`；key 从环境变量 `API_FOOTBALL_KEY` 读取，
  已写入用户级环境变量，任何脚本/输出均不落盘。
- 响应信封：`{get, parameters, errors, results, paging, response}`
- 当前账号：Free 计划，100 次/天，10 次/分；有效期至 2027-08-02。
- 免费版赛季限制：**仅开放 2022-2024 赛季**（实测 2025 赛季返回
  `Free plans do not have access to this season`）。
- 免费版限流：**10 次/分钟**（实测连发 18 个请求时第 11 个起被拒）；批量脚本必须限速，
  建议 ≥7 秒/请求，并处理 `errors.rateLimit` 重试。

## 2. 用法

```powershell
python api_football_adapter.py status
python api_football_adapter.py leagues --season 2024 --output leagues.json
python api_football_adapter.py teams --search "Manchester United"
python api_football_adapter.py fixtures --date 2026-08-02 --output fixtures.json
python api_football_adapter.py standings --league 39 --season 2024 --output standings.json
python api_football_adapter.py injuries --league 39 --season 2024 --output injuries.json
python api_football_adapter.py h2h --home 33 --away 34 --output h2h.json
```

子命令：`status` / `leagues` / `teams` / `fixtures` / `standings` / `injuries` / `h2h`。
`--output` 写入完整信封 JSON；stdout 只打印状态与预览（最多 10 条）。

## 5. 口径与边界（重要）

- API-Football 的 `/odds` 是博彩公司赔率（Bet365 等），**不是中国体彩固定奖金**，
  不能替代体彩官方链路，只能做 enrich。
- 免费版只开放 2022-2024 赛季；需要近期/实时赛季请升级 Pro（$19/月，7,500 次/天）。
- 大批量抓取前先用 `/status` 确认当日剩余额度。

## 7. apifootball.com 独立适配器

此前文件接入的是 `v3.football.api-sports.io`，不是 `apifootball.com`；两者不能共用
认证或响应解析。新增适配器源文件：
`02_脚本/apifootball_com_adapter.py`，运行入口同步到融合技能脚本目录。

- Base URL：`https://apiv3.apifootball.com/`
- 认证：查询参数 `APIkey`；只从环境变量 `APIFOOTBALL_COM_KEY` 读取，不落盘、不打印。
- 首期命令：`countries`、`leagues`、`events`、`standings`、`teams`、`lineups`、`statistics`。
- `--output` 保存完整 provider JSON；stdout 只输出最多 10 条标准化预览。
- 实测 `get_countries` / `get_leagues` 返回顶层 JSON 数组（不是固定 `{success,result}` 信封）；适配器已兼容两种结构。
- `lineups` 与 `statistics` 暂保留 provider 原始 `result`，待拿到真实样本后再固定字段映射，避免把未核验字段误接入模型。

```powershell
$env:APIFOOTBALL_COM_KEY = '<只在当前进程临时设置>'
python .\02_脚本\apifootball_com_adapter.py countries --output ..\04_素材\countries.json

python .\02_脚本\apifootball_com_adapter.py events --from-date 2026-08-01 --to-date 2026-08-02 --output ..\04_素材\events.json
```

不要把 `<只在当前进程临时设置>` 替换为文档中的真实 Key；若要持久化，请使用系统的
Secret 管理，不要写入项目文件、命令历史或提交记录。

### 8.1 响应结构与关键端点

| 端点 | 主要用途 | 响应形状/关键参数 |
| --- | --- | --- |
| `get_countries` | 账户套餐可用国家 | 顶层数组；`country_id/country_name` |
| `get_leagues` | 账户套餐可用联赛 | 顶层数组；可选 `country_id`；`league_id/league_name/league_season` |
| `get_teams` | 球队与球员列表 | `team_id` 或 `league_id` 二选一 |
| `get_players` | 球员查询 | `player_id` 或 `player_name` 二选一 |
| `get_events` | 赛程/赛果 | `from/to`，可选 `timezone/country_id/league_id/match_id/team_id/match_live/withPlayerStats` |
| `get_standings` | 积分榜 | `league_id`；字段以 `overall_league_*` 为主 |
| `get_lineups` | 单场首发/替补/教练/缺阵 | `match_id`；按 match id 包裹对象 |
| `get_statistics` | 单场比赛/球员统计 | `match_id`；按 match id 包裹对象 |
| `get_H2H` | 两队交锋与近期赛果 | `firstTeamId/secondTeamId` 或名称；分组对象 |
| `get_odds` | 博彩公司赔率 | `from/to` 或 `match_id`；仅外部参考，不替代体彩 |
| `get_predictions` | 供应商模型概率 | `from/to` 或 `country_id/league_id/match_id`；仅外部参考，不直接混入融合概率 |

接口认证统一通过查询参数 `APIkey`，但本项目只从 `APIFOOTBALL_COM_KEY` 读取。文档示例
存在不同响应形状：国家/联赛/赛程/赔率/预测多为顶层数组，首发/统计和 H2H 为对象；适配器
已对前两类和 match-id 对象做兼容，原始响应始终保留。

### 8.2 本项目的数据边界

1. 体彩官方赔率仍是体彩模型和推荐门控的唯一赔率源。`get_odds` 不能伪装为体彩链路；如选择外部赔率模式，必须显式标为 `apifootball_primary/provider_only`。
2. `get_predictions` 是供应商模型输出，不能当作独立事实或直接生成 edge；如使用，只做外部基准/消融对照。
3. `get_events` 的 `withPlayerStats` 会扩大响应体，默认不启用，只有明确需要时才请求。
4. 赛前特征必须区分赛前可得数据与赛后数据；赛后 `statistics`、球员表现不能回填到赛前输入。
5. 国家/联赛清单只证明当前订阅可见范围，不等于每个联赛都有完整历史、阵容或赔率覆盖。

## 9. 联赛训练改造入口

- `download_apifootball_com_history.py`：按 `league_id + 日期区间` 分月下载，输出原始响应和赛前安全的标准化 JSONL。
- `league_training_audit.py`：按现有样本自动将已标注的国内联赛分为 `independent`、`calibration` 或 `pooled`；未知、杯赛和洲际赛事默认排除。
- `provider_market_input.py`：把 `get_odds` 生成显式 `apifootball_primary/provider_only` 输入；拒绝把 `get_predictions` 当作市场或 edge。
- `team_strength.py --fit` / `--validate` 现可通过 `--league-id` 过滤；显式传入 `--results-only` 才允许使用无赛前赔率的赛果数据。此时市场基线返回 `UNAVAILABLE`，不伪造比较结果。
