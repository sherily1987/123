# APIFootball 端点对胜平负/比分的预测价值评估

日期：2026-08-11
范围：apifootball.com 官方文档列出的全部端点
定位：结论性评估，不改代码、不动训练链路。后续接入顺序以本文为准。

## 0. 结论速览

| 级别 | 端点 | 对 1X2 / 比分的作用 |
| --- | --- | --- |
| A | `get_odds` | 最强单一信号，同时约束 λ 总量与 λ 差 |
| A | `get_events` | 训练底料（DC/Elo），派生赛程密度类修正 |
| B | `get_statistics` | 历史射门→代理 xG，非市场数据中对比分增量最高 |
| B | `get_lineups` | 缺阵三分量的唯一可靠来源，T-60min 才可得 |
| B | `get_standings` | 冷启动先验 + 战意判断 |
| B | `get_players` / TopScorers | 给缺阵定权重，不直接进 1X2 |
| C | `get_predictions` | 非独立事实，只做消融基准 |
| C | `get_H2H` | 控制强度后增量接近零，有双重计数风险 |
| C | Live Odds / Livescore / WebSockets | 赛前无关，仅 CLV 采集与赛果回填 |
| C | Countries / Competitions / Teams | 零预测含量，价值在 ID 映射基建 |
| C | News / Videos / Widgets / Wordpress | 不进模型 |

## 1. 三条影响通道

引擎中胜平负与比分**不是两个模型**：两者都由同一对 λ（`λ_home`, `λ_away`）加 Dixon-Coles ρ
生成的比分矩阵聚合得到（见 `zu-yu-dashi-3/references/modeling.md`）。因此任何端点要影响预测，
只能走以下三条路之一：

| 通道 | 直接影响的输出 | 供给端点 |
| --- | --- | --- |
| λ 总量（进球水平） | 比分档位、O/U、BTTS | Odds(OU/TTG)、Statistics(射门/射正)、Standings(GF/GA) |
| λ 差（强弱差） | **胜平负**、让球、晋级 | Odds(1X2/AH)、Events→Elo/DC、Lineups 缺阵、Standings |
| 元数据 / 连接键 | 不产生预测，但决定训练是否被污染 | Countries、Competitions、Teams、Players |

判断一个端点值不值得接，先问它落在哪条通道、以及该通道是否已被更强的数据源占据。

## 2. A 级：决定性

### 2.1 `get_odds`

去水后的市场 1X2 基本是能拿到的最高准确度基线，也是 `market_only` / `hybrid` 两种模式存在的前提。
配合 OU/AH 走 `multi_market_fit` 时，λ 总量与 λ 差被同时约束，整张比分矩阵一次定形
（该求解路径不读 `goal_total`，见 modeling.md 的 solver 表）。

约束条件：

1. 必须是**赛前快照**并记录 `observed_at`。拿到收盘价甚至赛后价会让回测系统性虚高。
2. 按既有数据边界（`接入说明.md` §8.2），它是博彩公司赔率，标 `apifootball_primary/provider_only`，
   **不能替代体彩官方链路**，也不能用于体彩推荐门控。
3. 当前套餐已确认可取历史赔率，因此历史回测具备市场基线的条件。

### 2.2 `get_events`

训练底料。没有它就没有 DC 团队强度和 Elo，`model_first` 无从谈起。project021 已在做五大联赛
2021/22–2025/26 的下载。

常被忽略的附加价值：开球时间序列可以派生**休息天数、赛程密度、连续客场**，这些对 λ 有真实修正，
且完全是赛前可得数据，不引入泄漏。

## 3. B 级：实质修正，量级约 ±0.1~0.3 球

### 3.1 `get_statistics`

对**比分预测**而言，这是非市场数据里价值最高的一项。用历史场次的射门/射正构造代理 xG，
比直接用实际进球预测未来进球更稳——进球数有强烈的均值回归，射门量的信噪比更好。
对应 `fields_schema.md` 中的 `PROXY_XG` 状态（区别于 `EXPLICIT_XG`，本供应商不提供真实 xG）。

**红线**：待预测那场的 statistics 是赛后数据，绝对不能回填到赛前输入。project021 设计文档已把
`statistics` / `lineup` / `player_statistics` 列入禁止字段，接入时必须严格按 `match_id`
只取该场之前已完赛的比赛。

### 3.2 `get_lineups`

确认首发是 `attack_absence` / `defense_absence` / `gk_absence` 的唯一可靠来源。主力前锋或门将缺阵
对单场 λ 的影响很大，属于少数能在单场层面明显改写预测的独立事实。

限制：通常开球前约 1 小时才发布，早盘预测拿不到，此时只能用伤停/轮换先验顶上，
并在 `field_meta` 中如实标 `ASSUMED` 而非 `VALID`。

### 3.3 `get_standings`

独立增量不多——积分榜是 Events 的粗聚合，DC/Elo 已经把同一批赛果吃过一遍。两个不可替代的场景：

- 升班马、新赛季球队的**冷启动先验**；
- **战意**判断（保级、争冠、争欧战席位），直接喂 `motive` 与 `defense_risk`。

### 3.4 `get_players` / TopScorers

不直接进 1X2。作用是给缺阵定权重：判断某名缺阵球员承担了球队多少进攻份额，
把 `attack_absence` 从拍脑袋变成有依据的数值。射手榜类玩法才是它的主场。

## 4. C 级：谨慎使用或排除

- **`get_predictions`**：供应商模型输出，与市场高度相关，不是独立事实。混进融合概率等于把市场信号
  重复计权，还会伪造出假的 edge。只能作为外部基准做消融对照——`接入说明.md` §8.2 已如此规定。
- **`get_H2H`**：绝大部分信息 Events 里已有，控制球队强度后独立增量接近零，反而容易双重计数。
  只在跨联赛/杯赛的冷启动配对时作参考。
- **Live Odds / Livescore / WebSockets**：与赛前预测无关。真正用途有两个——抓收盘线做 CLV 评估、
  快速回填赛果。
- **Countries / Competitions / Teams**：零预测含量，但它们是 join key。ID 映射错误是训练数据
  静默损坏的头号来源，价值在基建不在模型。
- **News / Videos / Widgets / Wordpress**：非结构化、时效与可靠性都不足以进模型。

## 5. 两个天花板

1. **比分预测上限很低**：即使 λ 完美，Top1 比分命中率也就 12~14% 量级。新增数据对比分的改善，
   几乎全部走"λ 总量更准"这条路，而不是"选对了格子"。评估比分改进应看八档总进球分布的 MAE，
   而非 Top1 命中率。
2. **胜平负的天花板是市场**：内置 3504 场分档表显示，市场对平局的定价偏差各档均在 ±1.5pp 内，
   无系统性可利用偏差。引入这些数据的现实目标是让 `model_first` **逼近市场**并提供独立视角，
   而不是稳定击败市场。

## 6. 建议的后续接入优先级（本次不执行）

| 优先级 | 内容 | 关键约束 |
| --- | --- | --- |
| P0 | 赔率赛前快照：扩展 `provider_market_input.py`，增加 `observed_at` 与赛前时点校验，接上 `team_strength.py --validate` 的市场基线 | 历史赔率已确认可得；无法证明为赛前的赔率一律拒收 |
| P1 | 历史 `get_statistics` 下载 + 射门→代理 xG 特征 | 标 `PROXY_XG`，只用该场之前的比赛 |
| P2 | 固定 `get_lineups` 字段映射至缺阵三分量 | 标注可得时点 T-60min，早盘降级为 `ASSUMED` |
| P3 | `get_standings` 接入 `motive` 与升班马先验 | 不与 Elo 重复计权 |

每层的验证方式：时间顺序切分 60/20/20 不打乱，逐层加入后对比 1X2 Brier / log loss 与 O/U 2.5 Brier
（现有参照：TTG 直接去水 0.2362，先压缩为期望总进球再套 Poisson 0.2368）。
任一层无改善即不合入主链路，训练资产保持 `candidate` 标记。
