# APIFootball 联赛训练改造设计

日期：2026-08-11  
范围：`project007_APIFootball数据接入` 与融合技能的训练数据入口。

## 目标

把 `apifootball.com` 的历史赛果接入统一训练数据流，按实际数据质量自动决定每个赛事使用
独立联赛模型、联赛校准或全局池；不让赛后字段、供应商预测或不同赔率源破坏赛前回测口径。

## 非目标

- 不把 `get_predictions` 当作真值、标签或独立 edge。
- 不把赛后 statistics、球员评分、终场积分直接写入赛前特征。
- 不把杯赛、欧战、国家队赛事因样本量大而自动视为国内联赛模型。
- 不修改既有体彩默认链路；新增模式必须显式选择。

## 架构

```text
apifootball.com get_events / get_odds / get_predictions
        ↓
原始响应（含请求时间、来源、参数，不含 API Key）
        ↓
标准化历史赛果 + 可用性标签
        ↓
赛前字段白名单与泄漏审计
        ↓
联赛样本审计（按 league_id、赛季、时间切分）
        ├─ independent → 联赛独立 Dixon-Coles 团队强度模型
        ├─ calibration → 全局模型 + 联赛校准
        └─ pooled      → 全局模型
        ↓
时间外回测：独立模型 / 校准模型 / 全局基线 / 市场基线
```

## 数据契约

每条标准化赛果必须有：

```json
{
  "provider": "apifootball.com",
  "source_type": "event_result",
  "match_id": 123,
  "league_id": 152,
  "league_name": "Premier League",
  "season": "2025/2026",
  "kickoff": "2026-08-11T20:00:00+08:00",
  "home_id": 1,
  "home": "Home FC",
  "away_id": 2,
  "away": "Away FC",
  "actual": [1, 0],
  "status": "Finished",
  "collected_at": "2026-08-11T00:00:00+00:00"
}
```

训练只接收 `status=Finished`、明确 90 分钟主客进球、非取消赛事的记录。用
`provider + match_id` 去重；球队姓名只用于展示，建模键使用球队 ID。

## 赛前泄漏规则

| 字段类别 | 允许用途 |
| --- | --- |
| 赛前赛程、历史完赛结果、开球前已知积分 | 可构造训练特征，必须带时间截点 |
| 开球前已公布的首发/缺阵 | 可作为赛前事实，记录采集时间 |
| 比赛统计、球员评分、进球事件、最终积分榜 | `POST_MATCH`，禁止进入赛前特征 |
| `get_predictions` | `PROVIDER_BENCHMARK`，只用于平行回测 |
| `get_odds` | 市场源；保留博彩公司、赔率时间与原始赔率 |

## 自动分层规则

样本按 `league_id` 分组，按 kickoff 时间升序切成 60% 训练、20% 验证、20% 测试。

| 层级 | 条件 | 产物 |
| --- | --- | --- |
| `independent` | 国内联赛；至少 3 个赛季；完赛样本不少于 900；测试集不少于 150；球队 ID 覆盖率不少于 95%；球队数不少于 12 | 独立 Dixon-Coles 团队强度模型 |
| `calibration` | 完赛样本不少于 300，但不满足 `independent` | 全局模型上的联赛专属校准候选 |
| `pooled` | 其余赛事 | 使用全局模型，报告样本不足原因 |
| `excluded` | 杯赛、洲际杯赛、国家队赛事或赛事类别未知 | 不生成联赛独立模型 |

独立模型只有在时间测试集的 Brier 与 Log Loss 均不差于全局基线、且 ECE 不恶化时才可标
`VALID`；否则保存回测报告并回退到全局或校准层。任何样本在 100 场前不调整生产门槛，
200 场后才复审阈值。

## 赔率和供应商预测模式

| 模式 | 市场概率来源 | 输出标记 | 推荐门控 |
| --- | --- | --- | --- |
| `sporttery_primary` | 体彩官方赔率 | `sporttery` | 既有生产规则 |
| `apifootball_primary` | `get_odds` 去水后的指定博彩公司赔率 | `provider_only` | 单独回测与校准；不写成体彩推荐 |
| `dual_source` | 体彩与 API-Football 并列 | `dual_source` | 展示差异，不混合赔率 |

`get_predictions` 不参与三个模式的概率融合。它独立登记为供应商基准，按相同时间切分与
市场、全局模型和独立模型比较 Brier、Log Loss、ECE；没有通过该比较不得声称 edge。

## 实现边界

1. 增加 `apifootball_com` 历史下载器，按日期分块请求 `get_events`，保存原始与标准化文件。
2. 增加联赛样本审计器，输出分层、缺失字段、赛季数、球队覆盖率和切分范围。
3. 在团队强度训练入口增加按联赛过滤与结果-only 训练支持；有可对齐的赛前赔率时才报告市场基线。
4. 在适配器增加 `odds`、`predictions` 命令和明确的来源标签，不接入默认体彩预测路径。
5. 每个新增行为先写离线测试；真实 API 只用于小样本连通性验证，Key 不写入文件或日志。

## 验收

- 同一历史下载在重复运行时不重复保留相同 `provider + match_id`。
- 审计器把小联赛归入 `pooled`，满足全部门槛的国内联赛归入 `independent`。
- `POST_MATCH` 字段进入赛前训练输入时被拒绝并给出字段名。
- `apifootball_primary` 输出含 `provider_only`，不生成体彩玩法标签。
- 全部离线测试通过；真实 API 最少验证一次赛果下载与一次赔率/预测响应解析。
