# LLM 证据自动富集与 T−75 刷新设计

## 目标

修复 LLM 证据包把“已有但未装入”的数据误标为缺口的问题。首次生成证据时自动加入两队最近 5 场和体彩 CRS/TTG/HAFU；启动 watcher 后，在开球前约 75 分钟自动重拉伤停与首发，生成新的赛前证据快照。

## 现状与根因

- `mcp_evidence.py` 是实际结构化证据块生成器，`predict.py` 会把唯一的 `*_mcp.md` 拼入主证据。
- 体彩 raw 已有 CRS、TTG、HAFU，但证据块没有稳定渲染这些字段。
- 两个 `05/06_API_*球队.json` 只是球队身份搜索，不是最近赛程；API-Football 的 `fixtures?team=<id>&last=5` 实测可返回数据。
- 首发在 T−24 小时通常尚未公布；一次初始采集不足以覆盖临场信息。
- 生产代码在 `C:\Users\Administrator\football-llm-predictor`，F 盘仓库有独立副本；两边需保持新证据行为一致，但不能整文件覆盖。

## 方案

### 1. 首次证据富集

扩展 `mcp_evidence.py`，对每场生成以下可审计块：

1. 体彩市场块：从 raw match 原样读取 `model_odds`、`model_hhad`、`crs`、`ttg`、`hafu`，使用该场 `fixed_bonus_url` 和本次采集时间；不手算、不替换体彩语义。
2. 最近状态块：通过 API-Football v3 精确匹配本场 fixture，取得双方 API team id，再分别请求最近 5 场。输出比赛时间、赛事、主客队、90 分钟/已提供比分和状态；点球赛按 API 状态保留，不能把点球后结果冒充 90 分钟比分。
3. 伤停/首发块：请求本场 `injuries?fixture=<id>` 与 `fixtures/lineups?fixture=<id>`。0 条只能写 `UNAVAILABLE`，不能写“无伤停”。

API-Sports fixture 匹配必须同时核验双方名称、开球时间和赛事日期；不能只凭单一队名模糊匹配。无法唯一匹配时仅跳过 API-Sports 富集，保留体彩市场块。

### 2. T−75 watcher

在 `mcp_evidence.py` 增加：

```text
--watch-refresh
--refresh-before-minutes 75
--poll-seconds 60
```

执行流程：

1. 先完成初次证据生成。
2. 监控输入 raw 中的已选比赛。
3. 当 `0 < kickoff-now <= 75分钟` 时，每场只自动刷新一次伤停、首发及其它结构化数据。
4. 接口失败时在新快照中记录对应 `UNAVAILABLE`/错误摘要，其它证据继续生成。
5. 开球后不再刷新，不允许产生赛后伪赛前证据。

watcher 是一次启动、比赛范围内自动运行的进程；本轮不创建 Windows 全局计划任务。

### 3. 快照与预测读取

- 当前可供预测读取的文件继续保持唯一 canonical 名称：`evidence_NNN_*_mcp.md`。
- 每次刷新前，把旧 canonical 复制到 `out-dir/snapshots/`，文件名包含采集时间和内容哈希；随后原子替换 canonical。
- `predict.py` 仍只读取 canonical，`snapshots/` 不参与匹配，因此不会因多个历史文件造成证据歧义。
- canonical 与历史快照都必须包含 `collected_at`、source URL 和比赛身份；预测器继续拒绝开球后证据。

### 4. 代码边界

- C/F 两份 `mcp_evidence.py`：实现相同新接口和行为，保留各自已有功能差异。
- 新建小型纯函数模块 `llm_evidence_enrichment.py`：市场渲染、最近 5 场规范化、T−75 到期判断、快照归档；C/F 两份内容保持一致。
- C/F 两份测试：覆盖已有衍生市场不再丢失、最近 5 场格式、0 条伤停语义、T−75 边界、开球后拒绝刷新、旧快照保留。
- 不修改量化概率、`model_version` 或 `probability_signature`。

## 错误处理

- API key 缺失：体彩市场块仍生成，API-Sports 块标 `UNAVAILABLE`。
- fixture 匹配不唯一：不得猜测，写 `SOURCE_CONFLICT`。
- 最近场次少于 5 场：按实际条数输出并标覆盖不足。
- 首发/伤停 0 条：标 `UNAVAILABLE`，禁止解释为无人缺阵。
- watcher 被中断：已有 canonical 和 snapshots 保持有效；重新启动后根据 canonical 的刷新元数据避免重复刷新。

## 验收标准

1. 使用阿森纳 vs 曼城 raw，生成证据中能看到两队最近 5 场、CRS、TTG、HAFU。
2. 在可控时间测试中，T−76 不刷新、T−75 到 T−1 只刷新一次、开球后不刷新。
3. 刷新后 canonical 更新，旧文件存在 `snapshots/`，预测器只拼入 canonical。
4. C/F LLM 测试、project007/project021 测试和 football-quant-fusion 测试全部通过。
5. `audit_version_consistency.py` 确认概率签名不变。
