# Kimi K3 单模型迁移设计

## 目标

LLM 研究轨的新预测只使用 Moonshot API 模型 `kimi-k3`，完全移除 K2.6 的新调用路径。历史预测、报告和审计记录中的 `kimi-k2.6` 名称保持不变，不做追溯改写。

## 已核实前提

- 当前 Moonshot 账户的只读模型列表包含 `kimi-k3`。
- `kimi-k3` 已完成最小真实调用，能够返回正文。
- DeepSeek 仍只做中立证据审计；Kimi K3 与 GLM 是仅有的两个方向投票者。

## 修改范围

1. C 盘实际生产目录与 F 盘仓库副本的 `DEFAULT_MODELS`：将 `moonshot/kimi-k2.6` 替换为 `moonshot/kimi-k3`。
2. 将 K3 纳入模型级温度配置和推理模型输出预算；删除 K2.6 的当前生产配置。
3. 更新所有绑定当前默认模型池的单元测试、测试夹具与 README 当前配置说明。
4. C 盘生产版独有的 `model_weights.py` 只迁移当前模型键和同族分组，不改变既有权重数值；F 盘不引入该独有依赖。
5. 不改写 `data/` 下历史报告，不修改历史审计记录。

## 明确不做

- 不同时保留 K2.6 和 K3，避免同系列重复计票。
- K3 失败时不自动回退 K2.6；按现有双投票门控记录 `skip`。
- 不改变 DeepSeek 审计职责、GLM 投票职责、量化轨概率或发布版本。

## 验收标准

- 两个代码副本的新预测路径不再引用 `moonshot/kimi-k2.6`。
- 默认投票者为 GLM 与 K3，DeepSeek 不计票。
- C/F 两套 LLM 测试全部通过。
- 使用现有比赛证据完成一次真实 DeepSeek → GLM/K3 联调；无论形成共识还是 `skip`，均需留下结构化审计输出。
- `audit_version_consistency.py` 仍确认量化概率签名未变化。
