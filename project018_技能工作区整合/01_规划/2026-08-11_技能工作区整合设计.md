# football-quant-fusion 工作区整合设计

## 目标

将 `football-quant-fusion` 的可维护源码、核心依赖、LLM 对比轨、共享数据、测试、文档及插件源统一到 `F:\HM足球比赛预测\project018_技能工作区整合`，让 F 盘成为唯一事实源。Codex 仍可通过 C 盘的目录联接发现该技能，但 C 盘不再保存权威业务文件。

## 范围与非范围

纳入：融合技能、`zu-yu-dashi-3` 核心脚本、`football-llm-predictor` 源码和测试、共享回测库与数据集、插件清单及技能文档。

不纳入：Codex 自身运行时 Python、`node_modules`、`.venv`、插件缓存和测试缓存；这些是可由锁文件或安装流程重建的环境缓存，不是权威项目资产。

## 调用结构

```text
Codex 插件缓存 / 发现入口（C盘，仅联接）
  -> F盘 project018/02_脚本/skill/football-quant-fusion
  -> F盘 project018/02_脚本/core/zu-yu-dashi-3
  -> F盘 project018/04_素材/shared-data/football-quant-fusion
  -> F盘 project018/02_脚本/llm/football-llm-predictor
```

所有业务路径通过运行时路径配置解析；脚本不得再硬编码旧 `C:\Users\Administrator\.codex\skills\football-quant-fusion-suite` 或历史 `H:\` 工作区路径。

## 迁移策略

1. 对每个来源生成文件清单、SHA-256、大小和引用路径报告。
2. 以当前正在调用的 Junction 目标作为融合技能与核心引擎的初始候选；以共享回测库为数据初始候选。
3. 相同相对路径且哈希一致的副本只保留一份 canonical 文件；不同哈希文件不自动覆盖，先放入 `04_素材/迁移隔离/` 并记录差异。
4. 先复制并修复相对路径，再运行单元测试、CLI 冒烟测试、预测快照读取与回测只读核验。
5. 验收通过后才把 C 盘发现入口和插件源改为 Junction；旧目录改名为带日期的只读备份，观察期结束后才由用户授权删除。

## 兼容与安全约束

- `FUSION_CORE_DIR` 改为 F 盘 core 脚本目录；新增 `FUSION_WORKSPACE_ROOT` 与 `FUSION_DATA_ROOT`，由一个路径解析模块集中读取。
- 所有赛前冻结快照、回测结果和数据集保留原始字节内容及 SHA-256；不得重写历史预测或赛果。
- 插件 cache 只在 canonical plugin 已验证后以 cachebuster 重建；不得直接手改 marketplace。
- 外部 API key 仍只从环境变量读取，迁移过程不读取或写入密钥。

## 验收标准

1. `C:\Users\Administrator\.codex\skills\football-quant-fusion` 是指向 F 盘 canonical skill 的 Junction。
2. 所有生产脚本、核心脚本、LLM 源码和共享数据均有 F 盘 canonical 路径；不存在第二个可写生产源。
3. 路径扫描不再发现旧 `H:\claude AI自媒体` 或旧 suite 的生产硬编码；历史报告可保留旧路径但必须标为历史工件。
4. fusion、核心、LLM 三套测试全部通过；`fusion_cli.py --help` 能运行；已有预测与回测快照的 hash 和统计不变。
5. 插件 manifest 校验通过，重新安装后 Codex 能发现并调用技能。

## 回滚

切换前保留原始目录的日期备份及联接目标清单。任一验收失败时，将 Junction 和环境变量恢复到迁移前目标，不改写源数据。
