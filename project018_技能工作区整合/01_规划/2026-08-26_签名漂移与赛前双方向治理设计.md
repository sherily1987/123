# 签名漂移与赛前双方向治理设计

## 目标

在不改写历史预测、不调整概率参数、不开放生产推荐的前提下，完成两项治理能力：

1. 对同一模型版本下的概率签名漂移做逐签名、逐路由、全字段数值重放；只有完整等价时才建立精确别名并计入当前样本。
2. 将“主方向略优、防第二方向”变成预测时登记的版本化决策，而不是赛后根据概率重新推导。

本阶段只改变身份治理、决策登记和审计统计，不改变 `market_only` 概率、模型权重、校准参数、娱乐预算或生产推荐门禁。

## 当前事实

- 正式概率身份为 `model_version=m4`、`probability_signature=48d50abee08c...`。
- 正式发布锁与当前概率签名一致。
- 当前有效已结算样本为 48 场；样本量不足以触发自动重校准。
- 当前有 14 条同版本、不同签名记录被 `version-progress` 隔离。
- 已有 `probability_replay_check.py`、`release_governance.py`、`version_progress.py` 和发布锁，可在现有治理链上扩展。
- 历史记录中没有赛前持久化的备选方向时，不具备正式双方向计分依据。

## 不可突破的边界

- 原预测文件、原 `model_version`、原 `probability_signature`、原 `prediction_as_of` 和登记时间不得改写。
- 别名必须精确到 `model_version + probability_signature + route`，不得只按版本号合并。
- 等价结论只能覆盖实际重放过的路由和字段，不得外推。
- 任何赛后数据、缺失输入或时间穿越都会使该记录失去等价证明资格。
- 双方向只能随赛前预测登记；历史缺失字段不得赛后回填并进入正式命中分母。
- `production_recommendations_enabled=false` 保持不变。
- LLM 投票、娱乐策略、双方向覆盖命中不得进入模型概率、EV、Kelly或生产校准分母。

## 子系统一：签名漂移治理

### 分组身份

`version-progress` 将漂移记录按以下键分组：

```text
(model_version, probability_signature, route)
```

每组分别生成重放证明。一个签名在 `market_only` 等价，不代表它在 `hybrid`、`model_first` 或其他研究路由等价。

### 重放输入

每条记录必须保留并通过以下门禁：

- 原始赛前输入可读取；
- `match_id`、主客队、赛事和开球时间一致；
- `prediction_as_of < kickoff`；
- 输入中没有晚于 `prediction_as_of` 的证据；
- 原记录的路由明确；
- 当前代码的模型版本与目标发布身份明确。

任一条件不满足，记录标记为 `UNREPLAYABLE`，不参与别名合并。

### 全字段比较

重放至少比较以下正式输出：

- `final_1x2_pct`
- `model_1x2_pct`
- `score_matrix`
- `top_scores`
- `ou_2_5`
- `ou_3_5`
- `btts`
- `hafu_model`
- `ttg_score_consistency`

比较采用确定性数值规范化：键排序、固定浮点容差和数组维度检查。缺字段与值不同同样判为变化，不得把缺失静默补成默认值。

### 状态机

每组只能进入以下状态之一：

- `EQUIVALENT_ALIAS`：所有可重放记录的所有必需字段一致，并且整组没有不可重放记录；允许提交精确别名。
- `CHANGED_REQUIRES_VERSION_BUMP`：任一字段不一致；拒绝别名，要求升级模型版本。
- `UNREPLAYABLE`：原始输入、时间或身份证据不足；继续隔离。
- `PENDING_REVIEW`：机器证明完成但尚未通过人工发布评审；不能计入当前样本。

整组采用全有或全无原则。部分记录一致、部分不可重放时，不建立组别名。

### 重放证明

证明文件必须包含：

- 旧版本、旧签名和路由；
- 当前版本和当前签名；
- 场次数、逐场状态和输入哈希；
- 比较字段、容差和重放代码身份；
- `prediction_as_of` 审计；
- 结论、生成时间和报告哈希。

证明存放在 `project018_技能工作区整合/06_复盘/<日期>_签名漂移治理/`，不写入共享预测库。

### 精确别名

别名清单由通过评审的重放证明生成，禁止手工输入裸签名。结构至少包含：

```json
{
  "model_version": "m4",
  "probability_signature": "旧完整签名",
  "route": "market_only",
  "alias_to_model_version": "m4",
  "alias_to_probability_signature": "当前完整签名",
  "attestation_path": "重放证明路径",
  "attestation_sha256": "证明哈希"
}
```

发布锁校验别名目标与当前正式身份一致，并验证证明文件哈希。`version-progress` 和回测只能读取已发布别名；原预测记录保持原样。

## 子系统二：赛前双方向登记

### 数据契约

每场新预测增加不可变的 `direction_policy`：

```json
{
  "primary_direction": "H",
  "alternative_direction": "D",
  "classification": "PRIMARY_WITH_COVER",
  "probabilities": {"H": 0.394, "D": 0.298, "A": 0.307},
  "trigger": {
    "rule_version": "direction-policy-v1",
    "primary_margin_pp": 8.7,
    "primary_vs_alternative_pp": 9.6,
    "alternative_min_probability": 0.28
  },
  "prediction_as_of": "赛前时间",
  "model_version": "m4",
  "probability_signature": "完整签名",
  "direction_policy_signature": "仅覆盖方向分类配置与实现的完整签名",
  "direction_policy_signature_scope": "direction_policy_config_and_implementation"
}
```

方向编码固定为 `H/D/A`。概率保留三向完整值，不能只保存标题文本。

### 分类

- `PRIMARY_ONLY`：第一方向达到明确优势门槛，只登记主方向。
- `PRIMARY_WITH_COVER`：第一方向略优，第二方向达到覆盖门槛，登记主方向和备选方向。
- `UNCLEAR`：三向过于接近或敏感性过高，不强行登记可计分方向。
- `UNAVAILABLE`：概率、身份或时间契约不足。

阈值由版本化决策政策定义，不写入概率文件，因此修改阈值只改变方向对象内的
`direction_policy_signature`，不升级概率模型版本。模型 `build_identity` 中已有的
`decision_policy_signature` 是推荐/决策治理 bundle 的发布审计签名；它不是某场方向分类
对象的签名，也不得复制到 `direction_policy` 冒充方向证明。两者作用域必须分列展示。

### 登记门禁

- `direction_policy.prediction_as_of` 必须与预测快照一致并早于开球。
- 概率、模型身份和策略签名必须与同一输出一致。
- 同一预测快照只能登记一份方向政策。
- 新快照可以产生新方向政策，但必须保留旧快照，不覆盖历史。
- 结算后补写、缺少策略签名或概率不一致时拒绝登记。

### 结算

结算新增：

- `primary_hit`
- `alternative_hit`
- `direction_policy_hit`
- `official_result`
- `settlement_status`

`direction_policy_hit` 只表示赛前登记的方向集合是否覆盖官方90分钟赛果。它不得替代 `primary_hit`，也不得并入正式1X2 Top1命中率。

历史没有 `direction_policy` 的记录显示 `NOT_REGISTERED`，不能从历史概率重新生成后计分。

## 子系统三：只读治理报告

统一报告展示：

- 当前正式版本、签名和发布锁状态；
- 原始当前样本数；
- 等价别名样本数；
- 漂移、不可重放、变化和待评审组数；
- 每个别名覆盖的版本、签名、路由、场次和字段；
- `PRIMARY_ONLY`、`PRIMARY_WITH_COVER`、`UNCLEAR`、`UNAVAILABLE` 登记数量；
- 主方向命中、备选方向命中和方向集合覆盖命中的独立分母与指标；
- 版本准入结论。

报告只读，不自动修改权重、别名、发布锁或生产推荐开关。

## 错误处理

- 重放任务失败：保存错误和已完成逐场结果，整组保持隔离。
- 证明哈希不匹配：别名失效，回测停止把该组计入当前样本。
- 别名目标不是当前发布锁身份：拒绝加载。
- 双方向登记失败：概率预测仍可按原契约登记，但 `direction_policy` 标记 `UNAVAILABLE`；不得伪造方向。
- 旧记录缺少方向政策：正常结算官方结果，但不进入双方向统计。

## 测试与验收

### 签名治理

1. 当前14条漂移按完整签名和路由正确分组。
2. 全字段完全一致时生成重放证明和 `PENDING_REVIEW`。
3. 人工批准后的证明可生成精确别名。
4. 任一1X2、比分矩阵或衍生市场字段变化都进入 `CHANGED_REQUIRES_VERSION_BUMP`。
5. 输入缺失、赛后证据、时间穿越或路由不一致进入 `UNREPLAYABLE`。
6. 加载别名后样本数增加，但原预测文件哈希、登记时间和签名不变。
7. 证明被修改或发布锁变化后，别名立即失效。

### 双方向

1. 明确优势生成 `PRIMARY_ONLY`。
2. 略优且第二方向达标生成 `PRIMARY_WITH_COVER`。
3. 三向接近生成 `UNCLEAR`。
4. 赛后登记、概率不一致和策略签名缺失均被拒绝。
5. 新旧快照分别保留各自方向政策。
6. 主方向、备选方向和方向集合命中分别结算。
7. 历史无方向政策记录保持 `NOT_REGISTERED`。

### 回归与边界

- 发布锁、模型参数和历史预测文件前后哈希一致。
- `production_recommendations_enabled` 保持 `false`。
- 娱乐策略不得把双方向覆盖命中用于EV或校准。
- 修复当前使用固定2026-08-25开球时间的测试，改用相对未来时间或显式注入时钟，使完整测试套件不随日期自然失效。
- 专项测试、完整 football-quant-fusion 测试和发布锁检查全部通过后才可交付。

## 实施顺序

1. 扩展重放报告和漂移分组，不改变样本归属。
2. 增加证明审查与精确别名加载，验证14条漂移。
3. 增加方向政策生成与赛前登记。
4. 增加结算和独立统计。
5. 增加只读治理报告。
6. 修复时间敏感测试，完成全套回归。

## 非目标

- 本阶段不开发新的球队强度模型或证据特征。
- 不把 `hybrid-shadow` 提升为生产路由。
- 不重新拟合校准参数、HAD+TTG联合权重或衍生市场参数。
- 不开放生产推荐、EV或Kelly仓位。
- 不把100场或200场样本门槛解释为模型已经优于市场。
