# 融合技能数据统一与规则重构实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保留历史预测真实性和旧哈希链证据的前提下建立仓库内唯一事实源，统一生产路径，并把 `football-quant-fusion` 技能规则重写为可执行的分级门控。

**Architecture:** 先用只读盘点器建立来源基线，再由旁路迁移器生成 canonical registry、迁移映射和冲突清单；只有验证器通过后才允许生产入口切换。路径解析集中在 `runtime_paths.py`，技能主手册仅保留高频入口和不可突破的事实边界，历史与细节下沉到 references。

**Tech Stack:** Python 3.11、pytest、JSON/JSONL、SHA256、PowerShell、Git。

## Global Constraints

- 仓库内 `project018_技能工作区整合/04_素材/shared-data/football-quant-fusion/` 是唯一事实源。
- 历史预测概率、赛前时间、原始版本和原始来源不可改写。
- 旧记录不可重新标记为 `m1`；结构迁移只能标为 `schema_migrated`。
- 冲突记录不得静默覆盖；任何未解决内容冲突都会阻止自动切换。
- 原 registry 不原地修改；新 registry 必须旁路生成并形成独立哈希链。
- 体彩仍是竞彩生产赔率源；国际赔率只作移动赔率和 CLV 观察。
- 90分钟、加时、点球和晋级结果必须分开结算。
- 不修改与本任务无关的用户工作区改动。
