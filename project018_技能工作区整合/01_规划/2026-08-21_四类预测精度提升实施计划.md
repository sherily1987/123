# 四类足球预测精度提升实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task-by-task. Every code task begins with a failing test.

**Goal:** 在相同的赛前身份、90分钟赛果与版本边界下，持续改善并验证胜平负、精确比分、半全场、大小球四类输出。

**Architecture:** 先把现有登记预测中的全量比分矩阵、O/U2.5/O/U3.5 与半全场九态概率纳入统一评测。半全场真值从独立的、可审计的补充赛果取得，绝不由全场比分倒推。任何概率变更先作为影子候选，经时间留出集和同场基线比较后才有资格走新的版本化发布。

**Tech Stack:** Python 3.11、JSON/JSONL、pytest、既有体彩登记库、API-Sports / APIFootball 离线原始响应。

**Spec:** `AGENTS.md`、`02_脚本/skill/football-quant-fusion/SKILL.md`、本文件同目录的 `2026-08-21_模型改造1-6设计.md`。

## Global Constraints

- 体彩是唯一生产盘口；国际盘口与外部赛果仅用于研究、交叉验证或显式结算补充。
- 赛前记录不可改写；`prediction_as_of < kickoff` 和 90 分钟语义必须保持。
- 除已通过同源严格时间外验证的比分/大小球 λ3 候选外，不改变生产概率、不打开生产推荐；任何新候选仍须先通过其自身发布门禁。
- `score_ht` 必须带来源、采集时间、身份匹配依据与全场比分一致性校验；绝不由 `score_90` 推断。
- 比分指标使用完整 `score_matrix` 的实际比分概率，不能用 Top8 缺失值替代。
