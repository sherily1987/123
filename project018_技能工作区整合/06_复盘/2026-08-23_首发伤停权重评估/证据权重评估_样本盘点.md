# 首发、伤停与近期状态权重评估：样本盘点

## 结论

当前不能给首发、伤停或近期状态指定数值权重，也不能声称它们已经改善模型。

盘点 `backtest/registry.jsonl`：

| 项目 | 数量 |
|---|---:|
| 历史登记记录 | 1,712 |
| 保存统一 `evidence_audit` 的记录 | 0 |
| 有 `starting_xi.status=PREDICTED/VALID` 的记录 | 0 |
| 有 `injury.status=VALID` 的记录 | 0 |
| 有 `recent_form.status=VALID` 的记录 | 0 |

旧记录的概率和赛果可以用于市场基线回测，但不能用于“加入首发/伤停/近期状态前后”的成对消融比较。直接估权重会产生选择偏差和时间泄漏风险。

## 当前模型事实

- 生产 `market_only`：这些证据只做审计/门禁，不直接改写 `final_1x2`。
- 研究 `hybrid`：目前实际注入的是独立滚动 xG 的 `lambda_prior`，不是首发或伤停字段。
- 预计首发现在可标记为 `PREDICTED`，但仍需保留未确认风险标签；不能把它当成官方名单训练标签。

## 重新评估所需的最小数据结构

每场登记时保留同一 `match_id`、`prediction_as_of` 和开球前快照：

1. `starting_xi.status`、来源、采集时间、预计/官方标记；
2. 伤停/停赛名单、球员位置、预计出场权重和来源；
3. 最近5场及其赛事范围，区分正式赛与季前赛；
4. 市场基线概率、加入特征后的候选概率、90分钟赛果。

积累足够的时间外样本后，再按联赛和市场做 paired ablation：市场基线、只加首发/伤停、只加近期状态、全部加入。至少同时比较 Brier、LogLoss、ECE、CLV 和 ROI；任何单一指标改善都不能单独放行生产。
