# LLM 生产工程从 C 盘迁入仓库

## 背景

`AGENTS.md` 长期把这条列为**头号警告**：LLM 轨真正在跑的代码不在 git 仓库里，而在
`C:\Users\Administrator\football-llm-predictor\`（非 Git）；仓库里
`project018_技能工作区整合/02_脚本/llm/football-llm-predictor/` 是一份停更旧分支，
两边没有任何同步机制。

它造成过一次真实翻车：只查仓库 git 历史就断言「这个仓库没有任何代码计算 EV」，
而生产目录里 `ev_calculator.py` 一直在跑。本次迁移就是消掉这个分裂根源。

生产是它的严格超集，多 307 个文件。所以覆盖不丢东西。

体积：C 盘目录 401M，其中 `.venv` 约 350M、`node_modules` 7.5M。

## 迁移范围

**迁入**（399 个文件，磁盘 42M）：全部代码、文档、`data/`（含 `evidence_<日期>/` 证据留档
与 `raw_*.json` 流水线输入）、`scripts_legacy/`。

**未迁（必须在新位置重建）**：`.venv`、`node_modules`、`__pycache__`、`.pytest_cache`、
`.tmp_evi`。虚拟环境里烧死了创建时的绝对路径，拷到新位置是坏的。重建步骤已写进该目录
`README.md` §2.5。日常 pytest 不依赖 `.venv`，只有实际跑 Crawl4AI 抓取才需要。

**迁入磁盘但不入 git**（新增 `.gitignore`，120 项）：根目录 129 个一次性网页快照
`*.html`、`data/` 下的 `.tmp_evi*` / `.tmp_evidence_*` 临时抓取目录、
`wiki_*` / `wttr_*` / `espn*` / `sporttery_*` 等按赛事命名的一次性接口抓取。
文件仍在磁盘上照常可用，只是不进版本库。

**最终入库**：159 个新文件，4.30 MB。

## 密钥核查

迁移前扫过全部待入库文件，未发现真实密钥。密钥全部走环境变量
（`football_predictor.py` 读 `ZHIPU_API_KEY` 等，`mcp_evidence.py` 读 `API_FOOTBALL_KEY`），
目录里没有 `.env` 或密钥文件。

两处扫描告警均已确认为误报：`data/predictions_*.txt` 里的长十六进制是审计记录自带的
sha256（`prompt_sha256`/`evidence_file_sha256`）；某份证据 md 里的 `sk-` 命中是
`vasteras-sk-...`（韦斯特罗 SK 的新闻 URL 片段）。

顺带修掉一处真问题：`README.md` 的示例密钥行里写着 `「redacted:…」`——那是早前某次会话
把工具层遮蔽后的输出写回了文件。不是密钥泄漏，但照着复制会出错，已改为正常占位符。
