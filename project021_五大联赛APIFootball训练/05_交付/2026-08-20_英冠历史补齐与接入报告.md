# 英冠（fd_e1）历史数据补齐与接入报告

日期：2026-08-20
范围：用户上传的 football-data.co.uk E1（英格兰 Championship）8 个赛季 CSV，
补齐仓库原有 5 赛季（2021-22~2025-26）缺失的前 3 个赛季（2018-19/2019-20/2020-21），
用官方适配器重新全量拉取，训练强度模型并接入生产路由。

## 用户上传文件识别

E1 是 football-data.co.uk 对英冠（EFL Championship）的联赛代码（不是英甲）。
用户提供 8 个赛季 CSV（2018-19 ~ 2025-26），sha256 未核验（用户直接上传的原始数据，
非第三方打包），但队名阵容（莱斯特城/南安普顿/诺维奇/沃特福德等）与英冠身份吻合。

## 处理方式：改用官方适配器全量重拉，未采用用户 CSV 手工合并

第一次尝试用脚本合并用户 CSV 生成了 `championship_2018_2026_*.csv`（Elo/滚动特征工程
产物）到 `00_收件箱/`，**已放弃并删除**——原因：
1. 该产物的格式（宽表 + Elo 特征）与生产管线实际消费的 JSONL 事件格式不兼容；
2. 违反根目录/收件箱纪律（不应在收件箱堆放训练中间产物）；
3. 手工队名对齐存在拼写风险，不如用已验证的官方适配器统一处理。

改用 `project007_APIFootball数据接入/02_脚本/football_data_couk_adapter.py`
（与 `fd_d2`/`fd_usa` 同一条已验证路径）直接从 football-data.co.uk 官网重新拉取
E1 全部 8 个赛季：

```bash
python football_data_couk_adapter.py --league E1 \
  --seasons 1819 1920 2021 2122 2223 2324 2425 2526 \
  --output-dir 04_素材/标准化 --raw-dir 04_素材/football_data_couk_raw
```

结果：4416 场（此前 5 赛季约 2760 场），收盘赔率覆盖 100%，44 支球队，
射正统计可用 4415/4416（99.98%）。用户上传的原始 CSV 未直接入库，只作为
触发补数据的信号来源。

## ⚠️ 第二个中途事故：重跑 run_full_backtest.py（不带 --only）覆盖掉日职的手工合并条目

跑全量 `run_full_backtest.py --report full_backtest.json`（无 `--only`）刷新报告时，
覆盖掉了此前 `calibrate_japan_j1.py`（08-16）手工合并进 `full_backtest.json` 的
`apisports_japan_j1_league` 特殊校准条目——该联赛数据源是 api-sports xG 场次 +
fd_jpn 收盘线按开球日±1天+队名对齐拼接（`apisports_japan_j1_league_events_closing_attached.jsonl`），
不在 `run_full_backtest.discover()` 的标准自动发现范围内（既不是
`*_events_provider_market.jsonl` 也不是 `fd_*_events.jsonl` 命名规则），因此每次
不带 `--only` 的全量重跑都会丢失这条，必须事后手工合并回去。

已用 `pytest` 发现（`test_japan_j1_mapping.py::test_full_backtest_has_japan_xg_closing_tier_inputs`
KeyError），重跑 `calibrate_japan_j1.py` 补生成 `japan_j1_calibration.json`，
再手工把 `apisports_xg_vs_closing_joined` 结果合并回 `full_backtest.json`
（含重算 `summary_by_baseline.closing_market` 分组）。修复后 133 项测试全部通过，
`predict_no_odds.league_tiers()` 确认 `apisports_japan_j1_league` 恢复 B 档
（gap 0.0113，与 08-16 报告记录一致），`fd_e1` 保持 A 档不受影响。

**教训（已知晓，未改代码）**：任何全量重跑 `run_full_backtest.py` 之后，若涉及
日职，必须重跑 `calibrate_japan_j1.py` 并手工合并，否则该联赛的分档裁决会静默
丢失（不会报错，只是从 tiers 字典里消失，下游 `predict_no_odds.py` 遇到日职时
会拿不到 tier 信息）。更根本的修法是把 `apisports_japan_j1_league` 的特殊拼接
逻辑也纳入 `run_full_backtest.discover()` 的自动发现规则，但这超出本次任务范围，
未动代码，只记录在案。
