## 1. 问题

`team_strength.py` 的 `load_matches` 用**队名字符串**当球队身份：

```python
"home": r.get("home"), "away": r.get("away"),
```

而下载器其实已经落了 `home_id` / `away_id`，一直没被使用。

apifootball.com 的队名跨赛季不稳定。以英超为例，1908 场赛果里 **27 个 team_id 对应 41 种队名**：

| team_id | 出现过的队名 |
| --- | --- |
| 102 | `Manchester United`（2021-08→2025-05）、`Man Utd`、`Manchester Utd`（2025-08→2026-05） |
| 80 | `Manchester City`、`Man City` |
| 3089 | `Nottingham`、`Nottm Forest`、`Nottingham Forest` |
| 3071 | `Bournemouth`、`AFC Bournemouth`、`Bournemouth FC` |

同一支球队被拆成 2~3 个身份，产生两种故障：

1. **改名发生在测试期** → 该队在测试期的队名训练集里从没出现，`predict_match` 返回
   `UNFITTED_TEAM`，整队比赛被跳过。英超测试集 379 场里 **136 场（36%）** 就是这么丢的。
2. **改名发生在训练期** → 不跳过，但一支队的历史被劈成两半各自拟合，评分严重稀释。
   德甲 `skip=1` 却 Brier 0.732，就是这种。

各联赛"队名虚增"与测试集表现高度相关，法甲虚增仅 +1，是修复前唯一健康的联赛：

| 联赛 | team_id | 队名 | 虚增 | 修复前测试 Brier |
| --- | ---: | ---: | ---: | ---: |
| 英超 | 27 | 41 | +14 | 0.8878 |
| 德甲 | 28 | 40 | +12 | 0.7322 |
| 西甲 | 26 | 36 | +10 | 0.6294 |
| 意甲 | 27 | 31 | +4 | 0.6563 |
| 法甲 | 27 | 28 | **+1** | **0.5815** |

## 2. 改动

1. 新增 `team_key(row, side)`：有 `<side>_id` 时返回 `id:<tid>`，否则退回队名。
   `id:` 前缀避免与真实队名相撞；无 id 的数据源（football-data.co.uk 等）行为与改动前一致。
2. `load_matches` 用主键填 `home`/`away`，并保留 `home_name`/`away_name` 供显示。
3. 新增 `build_team_identity(matches)`：产出 `team_names`（主键→最近队名）与
   `team_aliases`（历史队名→主键）。**同一队名指向多个 team_id 直接抛
   `AMBIGUOUS_TEAM_NAME`**（真重名，不可静默合并）；同一 id 多个队名收进别名。
4. 模型 JSON 新增 `team_names`、`team_aliases` 两个字段。
5. 新增 `team_index(model)`：主键与任一历史队名都能命中。`predict_match` 与 `validate`
   改用它。旧模型文件没有 `team_aliases` 时退化为纯主键查找，向后兼容。

外部调用方（如 `apifootball_model_features.py` 用队名查模型）无需改动。

说明新纳入的这批比赛本身更难。正确读法是看**同一子集内模型与市场的差距**：
